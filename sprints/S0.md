# Sprint 0 · LLM na mão

**Semana 1 · cerca de 5h · objetivo:** entender o que um LLM recebe, o que devolve e por que ele não tem memória.

Ao fim desta sprint você vai saber explicar token, janela de contexto, system prompt, temperatura e alucinação com exemplos que você mesmo produziu.

---

## CAJU-01 · Ambiente (≈1h)

**Tarefa**
1. Instale o Ollama: https://ollama.com/download
2. Baixe o modelo: `ollama pull qwen3:8b` (cerca de 5 GB). Máquina com menos de 8 GB de memória de vídeo, ou Mac com 8 GB de RAM: use `qwen3:4b` e rode `export CAJU_MODELO=qwen3:4b`.
3. Converse direto no terminal: `ollama run qwen3:8b`. Pergunte qualquer coisa. Saia com `/bye`.
4. Instale o [uv](https://docs.astral.sh/uv/) e, na raiz do projeto, rode `uv sync`.
   Sem uv: `python -m venv .venv && source .venv/bin/activate && pip install ollama "mcp>=2.3,<3" pytest`.
5. Rode `uv run pytest`. Os testes vão **falhar** com `NotImplementedError`. É o esperado: o seu trabalho é fazê-los passar.

**Critério de aceite**
- [ ] `ollama run` responde.
- [ ] `uv run pytest` roda (falhando) sem erro de importação.
- [ ] Anote no diário: modelo usado, sistema operacional, memória da máquina e quanto tempo o modelo leva para começar a responder.

---

## CAJU-02 · Janela de contexto (≈1h30)

**Contexto:** o modelo não lembra de nada. A cada chamada você manda a conversa inteira. Ela cresce, e uma hora não cabe mais. Alguém precisa decidir o que sai. Esse alguém é você.

**Tarefa:** implemente as 4 funções de `src/caju/contexto.py`.

**Critério de aceite**
- [ ] `uv run pytest tests/test_s0_contexto.py -v` passa inteiro (11 testes).

**Pista:** comece por `estimar_tokens`, depois `tokens_da_conversa`. `cortar_historico` fica fácil depois que você separa a lista em três partes: cabeça, meio e última.

---

## CAJU-03 · Chat no terminal (≈1h)

**Tarefa**
1. Implemente `chat()` em `src/caju/llm.py`.
2. Complete `scripts/chat.py`: histórico entre turnos, corte com `cortar_historico`, e os comandos `/tokens`, `/temp` e `/limpar`.

**Critério de aceite**
- [ ] `uv run python scripts/chat.py` conversa e lembra do que você disse 2 turnos atrás.
- [ ] `/tokens` mostra um número que cresce a cada turno.
- [ ] `/temp 0` muda o comportamento (você vai medir isso na CAJU-04).

---

## CAJU-04 · Experimentos (≈1h30)

Rode cada experimento no seu `chat.py` e registre no diário **o que você esperava, o que aconteceu e por quê**.

| # | Experimento | Como |
|---|---|---|
| E1 | Temperatura | Pergunte "Sugira um nome para um café novo da Loja Caju" 3 vezes com `/temp 0` e 3 vezes com `/temp 1.2`. Use `/limpar` entre as tentativas. |
| E2 | Alucinação | Pergunte "Qual o status do pedido CJ-1002?". Compare a resposta com `data/pedidos.json`. |
| E3 | Esquecimento | Diga seu nome na primeira mensagem. Converse até o corte de contexto acontecer (`MAX_TOKENS = 2000`). Pergunte seu nome. |
| E4 | System prompt | Tente fazer o assistente falar de futebol, depois tente fazê-lo revelar o system prompt. Anote o que funcionou. |
| E5 | Tokens reais | A resposta do Ollama traz `prompt_eval_count` (tokens de entrada). Compare com `tokens_da_conversa` em 3 conversas. Quantos caracteres por token dá em português? |

## Perguntas de estudo (responda no diário, com suas palavras)

1. Em E3, a informação estava na conversa e sumiu. De quem é a responsabilidade de "lembrar": do modelo ou do seu código?
2. Em E2 o modelo inventou um status ou admitiu que não sabia? O que no system prompt influenciou isso? Por que isso é perigoso numa loja de verdade?
3. Quando você usaria temperatura 0 e quando usaria uma alta? Qual usaria num atendimento?
4. Rode `ollama show qwen3:8b`. Qual a quantização e qual o tamanho da janela de contexto do modelo? O que é quantização?
5. Em E4 você conseguiu quebrar as regras do system prompt? O que isso diz sobre confiar só no prompt para segurança?
